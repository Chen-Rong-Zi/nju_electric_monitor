# 前端重构设计文档

> 将 nju_electric_monitor 前端重构为 njupower 风格的 Apple 设计系统，增加小时级精细化分析功能

**日期:** 2026-08-01
**状态:** 设计定稿

---

## 1. 目标

将当前单页前端（602行，Plotly.js）重构为 njupower 风格的 Apple 设计体系，使用 Chart.js 替换 Plotly.js，并增加小时级精细化分析功能，充分利用每小时数据粒度的价值。

## 2. 架构选型

| 维度 | 决策 |
|------|------|
| 页面结构 | 单页 + 标签分段切换（概览 / 分析 / 数据明细） |
| 图表库 | Chart.js 4.4.0（CDN 加载） |
| 代码组织 | 单 HTML + 独立 JS 模块 |
| 数据缓存 | sessionStorage |
| 颜色系统 | 保留当前 OKLCH 色板，与 njupower 一致；毛玻璃效果使用 `backdrop-filter`，导航栏/标签栏沿用现有配色方案，不额外引入 Apple HIG 颜色变体 |
| 部署 | GitHub Pages，单目录多文件（index.html + js/ 模块） |

## 3. 文件结构

```
docs/
  index.html                    # 主页面（HTML + CSS）
  js/
    data-service.js             # 数据加载、缓存、解析
    analytics.js                # 所有分析计算函数
    chart-config.js             # Chart.js 图表配置与渲染
    ui-controller.js            # UI 更新、标签切换、事件绑定
```

## 5. 数据流

```
electricity_data.json (JSONL)
  → fetch() → parse lines → JSON.parse()
  → processData() (北京时间转换 + 排序)
  → sessionStorage 缓存
  → calcDiffs() (相邻差值，标注充值)
  → 各分析函数计算
  → UI 渲染
```

## 6. 核心算法

### 异常检测
- 滑动窗口：最近 30 天的小时数据
- 计算窗口内每个小时用电量的平均值和标准差
- 当前值 > 平均值 + 2×标准差 → 标记为异常点（红色标记）

### 模式识别（高峰/平峰/低谷）
- 按小时计算平均用电量
- 排序后取 top 25% 为高峰，bottom 25% 为低谷，中间为平峰
- 合并连续小时区间

### 用电速度
- 最近 N 个有效差值的平均 / 小时数
- 与上周同时段速度对比

### 预警等级
- 正常: > 50 度
- 注意: >= 20 度且 <= 50 度
- 警告: >= 10 度且 < 20 度
- 紧急: < 10 度

### 趋势加速度
- 计算 7 天滑动平均用电量
- 拟合线性斜率，对比前后两个 7 天窗口的斜率变化

## 7. 类比系统

沿用 njupower 的类比数据，根据用电量自动匹配最佳类比。匹配规则：按表格顺序从上到下遍历，选择第一个区间命中用电量的类比（区间越窄越优先，最后回退到通用类比"木材燃烧"）。

| 类比 | 因子 | 适用区间 |
|------|------|----------|
| 烧开水 💧 | ×10 升 | 0-1 度 |
| LED 照明 💡 | ×100 小时 | 0.5-3 度 |
| 手机充电 📱 | ×67 次 | 1-5 度 |
| 笔记本工作 💻 | ×20 小时 | 2-8 度 |
| 空调制冷 ❄️ | ×1 小时 | 5-15 度 |
| 洗衣机 🧺 | ×2 次 | 3-10 度 |
| 电动车骑行 🚲 | ×50 公里 | 1-20 度 |
| 木材燃烧 🪵 | ×0.22 kg | 通用 |
